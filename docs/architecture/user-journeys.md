# Top-level User Journeys

## Purpose

Capture the main product flows without specifying screens, APIs or component structure.

## Learner journeys

### Explore knowledge

Open the knowledge space, search/filter the graph, inspect clusters and relations, select a node and read its semantic detail.

### Define a target

Select a domain, cluster or arbitrary subgraph and save it as the intended learning scope.

### Build a learning plan

Turn the target scope into prioritized coverage, inspect what is already known/active/unstarted, and choose which domain-specific learning material should be produced.

### Publish and study

Generate/reconcile learning objects into a study runtime such as Anki, then study there using its scheduler and interaction model.

### Review progress

Return to Prep and view the target graph with learning-state overlays; inspect weak regions, missing coverage and current plan progress.

## Operator/curation journeys

### Import knowledge

Provide structured files or source material, inspect proposed graph changes, and accept only validated semantic additions/updates.

### Diagnose graph/content quality

Inspect duplicate/conflicting candidates, unsupported relations, learning-content problems and external synchronization conflicts.

## Boundary

These are top-level journeys. Screen decomposition, command/API contracts, workflow steps and detailed error behavior are later design responsibilities.
