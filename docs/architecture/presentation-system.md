# Presentation System Design

## Stack

- React;
- TypeScript;
- browser/WebGL delivery;
- `react-force-graph-3d` as initial graph renderer;
- normal HTML/CSS components for search, filters, tables, forms and detail panels.

The graph renderer is wrapped behind a project-owned component so domain/application code never imports renderer types.

## View-state architecture

Client state is separated into:

```text
server query state
  -> graph DTO / details / plans / curation status

personal transient view state
  -> camera, selection, hover, open panels

saved view state
  -> filters, visible relation types, pinned subjects, selected overlay
```

Coordinates/layout generated by the renderer are not semantic graph data.

## Rendering strategy

- request bounded subgraphs from the backend;
- progressively expand neighborhoods;
- degrade labels/effects as density increases;
- support 2D/list/table/detail alternatives;
- retain selected node/detail context while filters/layout change.

## Overlay discipline

Semantic kind/relation type and learner-state/plan overlays use separate visual channels/modes; one color channel is not overloaded with multiple meanings.

## Replaceability

Renderer-specific data conversion occurs at one adapter/component boundary. Replacing the 3D engine must not change API/domain contracts.
